# 项目任务书：视觉定位驱动的仿真抓取与部署

[学习计划](README.md) · [资源](RESOURCES.md) · [实验模板](TEMPLATES.md#experiment)

状态：**任务定义，尚未实现或验证**。本文件中的指标是待测项，不是已完成成果。

## 任务与范围

固定相机下，对桌面上少量简单物体进行检测，利用深度估计位置，将目标变换到机器人基坐标，控制夹爪执行抓取。第一阶段成功定义为稳定抬升；可行时扩展到指定区域放置。

主任务只选一套机械臂与夹爪，物体尺寸适配夹爪，采用自上而下的简化抓取。默认仿真，无真机假设。物体形状、桌面范围、相机位置、初始状态和成功阈值在正式评估前固定。

视觉链路：RGB-D → 检测框／类别／置信度 → 目标区域深度 → 三维抓取位置估计 → 相机到基坐标变换 → 动作接口。

执行链路：接近 → 对齐 → 下降 → 闭合 → 抬升 → 可选放置 → 成功检查或超时。

检测框不是抓取姿态。第一版使用受约束物体与固定抓取方向，并明确可见表面位置、物体中心、夹爪中心的差别；不宣称适用于任意物体。

## 技术选择

| 部分 | 默认选择 | 选择原则 |
| --- | --- | --- |
| 检测 | 已熟悉的 PyTorch 模型；没有现成代码时参考 TorchVision | 先取得可信基线，避免同时比较多个框架 |
| 几何 | NumPy＋OpenCV | 明确内外参、单位、坐标方向和深度含义 |
| 仿真 | robosuite＋MuJoCo | 使用已有机械臂、任务与控制器 |
| 部署 | ONNX Runtime，Python 路径后接 C++ | 先验证一致性，再评估性能 |
| 消息接口 | 直接模块调用；ROS 2 按岗位需要添加 | 避免先搭复杂通信再验证算法 |

C++ 第一版最低要求是一个可构建、可调用的核心模块。完整 C++ 推理来不及时，可完成几何或后处理模块，并如实界定能力范围。

<a id="evaluation"></a>
## 评估规范

### 三类结果

1. **真实位姿诊断基线**：使用仿真物体位姿，检查控制链路与任务本身是否可行。仅作为诊断参考，不保证它构成严格理论上界。
2. **视觉基线**：使用图像、深度和已定义的相机标定信息生成动作，不读取物体真实位姿作为输入。
3. **视觉改进**：只改变已明确的感知或定位环节，其余条件与基线一致。

评估器可以读取真实位姿计算定位误差和成功状态，但这些数据不得回流给最终视觉方案决定动作。

### 指标

| 环节 | 至少记录 | 避免的问题 |
| --- | --- | --- |
| 检测 | AP／Recall、置信度阈值、类别与条件分组结果 | 只报训练损失或只展示容易样例 |
| 定位 | 三维误差中位数、P95，单位；有效深度比例 | 混淆米／毫米、深度 Z 与距离、坐标变换方向 |
| 执行 | 成功次数／总次数、超时、失败类型、每次运行 ID | 把人工干预或真实位姿辅助结果算成视觉成功 |
| 部署 | 硬件、输入尺寸、batch、精度、运行后端、预热、P50／P95 延迟 | 将不同硬件或不含预后处理的数字直接比较 |

成功阈值根据任务确定，执行前写入配置：抬升高度、保持时长、是否脱落、放置区域、最大步数。不要看完结果后修改成功标准。

W07—W08 至少做 50 次预定义场景的阶段性评估。最终每个主要条件建议至少 100 次，报告分母；样本较少时明确不确定性，可给出二项比例区间。基线与改进使用同一套场景配置和种子。比较训练方法时预算允许应重复训练种子，只有单次训练时明确局限。

### 困难条件只选一个主轴

候选：背景变化、目标位置变化、深度噪声、有限遮挡。根据基线中主要失败原因决定，不同时扩展全部条件。超出视野、不可达等无效场景需在测试设计时明确处理规则，不能事后挑掉失败样例。

### 改进要求

记录“观察 → 假设 → 修改 → 验证 → 结论”。可尝试针对性的增强、目标区域深度过滤、定位方法调整；不强制改网络结构。改进无效也应保留负结果及分析，不编造性能提升。
