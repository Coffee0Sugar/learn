# 16 周视觉算法工程化与机器人视觉学习计划

制定日期：2026-10-11。执行时间：**2026-10-12—2027-01-31**。正式求职：**2027 年 2 月起**。时间预算：每周约 14 小时，共约 224 小时。

导航：[资源索引](RESOURCES.md) · [项目任务书](PROJECT.md) · [进度清单](PROGRESS.md) · [记录模板](TEMPLATES.md) · [仓库首页](../../README.md)

## 目标与适用基础

适合已有目标检测、PyTorch、C++／Python 基础，希望将视觉模型训练经验扩展到部署和机器人视觉应用的学习者。

- 主投方向：CV 算法工程化、视觉感知、模型部署相关岗位。
- 拓展方向：机器人视觉、RGB-D 感知、视觉引导操作。
- 求职区域：优先成都；以实际社招岗位要求调整学习内容。
- 1 月底的目标是具备投递和面试材料，不把学完课程等同于拿到 offer。
- 前 12 周不并行开展完整 Agent、ACT、VLA 或强化学习项目；选学不能挤占主项目、旧经历复盘和面试时间。

本文件为公开学习计划，不记录个人薪资、雇主内部信息或未公开项目材料。薪资底线、联系方式和具体投递反馈另存私人笔记。

## 三份最终成果

1. **既有 CV 项目复盘**：任务、数据、基线、本人贡献、指标、误检漏检分析和局限；只填写有依据的结果。
2. **两个工程问题案例**：现象、定位证据、根因、方案取舍、验证结果；区分个人贡献与团队工作。
3. **一个新项目**：固定相机桌面场景的检测、三维定位、仿真抓取与推理部署。视觉模块能独立使用，机器人执行是拓展能力。

## 三道检查点与减负规则

### W02：基础环境与任务是否成立

必须能运行检测评估和仿真示例。不能正常运行时，先用已有示例和单物体任务，不自行搭建整套机械臂模型。单个环境问题超过一个集中调试时段，记录错误、尝试和最小复现，再决定切换环境。

### W08：是否已有可测量的完整流程

必须有一份基线报告。若视觉模块已可用而机器人执行不稳定，保住检测、定位与部署成果，将任务降为抓取抬升，暂缓放置；必要时明确项目仅完成感知模块，不宣称完成机器人闭环。不要为补进度临时引入 ACT、SLAM 或 Agent。

### W12：停止扩展功能

之后主要做复现、材料、编程和面试。ROS 2 是按岗位需要选择的接口练习，不能挤占最终报告。没有真机时写明“仿真验证”，不将其包装为真机落地。

## 环境与资料使用原则

- 第 1 周确认操作系统、可用算力和预算；硬件尚未确认，不承诺训练时长。
- 优先一套检测代码和一套仿真任务；robosuite 作为任务层，MuJoCo 作为底层参考，不是两个独立项目。
- robosuite 官方说明支持 macOS 与 Linux；macOS 的默认查看器有启动方式要求，按 [R04 官方安装页](RESOURCES.md#r04) 检查。检测训练设备支持需单独验证。
- 初始采用已能正常运行的兼容版本组合，然后锁定依赖、配置和随机种子；不要在项目中途盲目追最新版本。
- ROS 2 按所选发行版的系统要求另行准备；不假设当前电脑可以原生安装所有组件。
- 不把数据集、模型权重、大视频或密钥直接提交到普通 Git 历史；提供来源、下载方式和必要的使用许可说明。
